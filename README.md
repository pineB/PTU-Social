# ПТУ-Сошиал

Клиентская платформа для студента, преподавателя, организатора мероприятий и учебной части. Учебные показатели и списки отображаются на основе локальных данных и готовы к подключению API.

## Запуск

```sh
npm install
npm run dev
```

Для production-сборки выполните `npm run build`, для локального просмотра сборки — `npm run preview`.

## Маршруты

- `/student` — кабинет студента
- `/student/profile` — профиль студента и история начислений
- `/student/tasks` — список заданий и форма сдачи
- `/student/events` — мероприятия и запись
- `/student/group-confirmation` — подтверждение заявок старостой
- `/student/wallet` — баланс и история операций
- `/student/battle-pass` — все 50 уровней в одной горизонтальной шкале, бесплатная и премиальная дорожки, прогресс только за АР
- `/student/inventory` — отдельный инвентарь с анимированным открытием выданных кейсов
- `/student/certificates` — заявка на справку и её статус
- `/academic-office/certificates` — обработка заявок на справки
- `/academic-office/schedule` — создание и просмотр расписания занятий по дням
- `/teacher` — кабинет преподавателя
- `/teacher/submissions` — таблица сдач студентов и проверка работ
- `/teacher/events` — создание мероприятий, запись закреплённых групп и начисление БОА/БУА после завершения
- `/organizer` — кабинет организатора мероприятий
- `/organizer/events` — управление мероприятиями и подтверждёнными участниками
- `/academic-office` — кабинет учебной части
- `/register` — заявка студента
- `/verify-email` — подтверждение электронной почты
- `/teacher/activate?token=...` — установка пароля по приглашению преподавателя

Корневой и неизвестные маршруты перенаправляются в кабинет студента. Базовый URL API задаётся переменной окружения `VITE_API_BASE_URL`; если она не задана, используется `/api`.

Светлая или тёмная тема переключается кнопкой в верхней панели и сохраняется для следующих посещений.

Формы регистрации, проверки кода и активации приглашения пока работают как демонстрационный сценарий на клиенте; для реальной проверки и создания учётных записей требуется подключить серверный API из OpenAPI-спецификации.

Список заданий и таблица сдач также используют демонстрационное состояние в памяти приложения. Условие задания видно непосредственно в карточке; отправленная работа и имя файла отображаются преподавателю в таблице и окне просмотра. При принятии преподаватель выбирает оценку, может добавить комментарий и файл; при возврате комментарий обязателен, файл можно добавить. Студент видит отзыв и имя вложения в карточке. Награда АР рассчитывается с учётом коэффициента оценки и просрочки. В текущем демонстрационном режиме сохраняются только имена вложений; для загрузки и скачивания содержимого требуется серверное хранилище/API.

Мероприятия, групповая запись, начисления, кошелёк, батл-пасс, инвентарь и заявки на справки используют общее демонстрационное состояние в памяти приложения. Для индивидуального мероприятия студент записывается самостоятельно. Для коллективного мероприятия преподаватель записывает закреплённую группу, а староста — свою; студенты этой группы подтверждают намерение участвовать. Группу допускают, если число подтвердивших не меньше `ceil(численность × порог / 100)`; в противном случае групповое начисление недоступно. После завершения создатель мероприятия — преподаватель или организатор — указывает каждому участнику процент активности от 0 до 100. Начисление рассчитывается как `round(максимум баллов мероприятия × процент / 100)`; максимальное число баллов задаётся при создании события. Отдельного бюджета баллов у преподавателя или организатора нет.

Только участник мероприятия может оставить один отзыв после его завершения; до этого форма отзыва не отображается. Мероприятия с ожидающими отзывами можно открыть кнопкой-счётчиком над списком, а форму внутри карточки раскрыть отдельной кнопкой. Создатель модерирует отзыв, одобрение начисляет 5 единиц валюты (не более пяти наград за месяц в демонстрационном сценарии). Студенческий батл-пасс получает опыт только за АР: 20 АР дают уровень; все 50 уровней показаны в единой горизонтальной прокручиваемой шкале с неподвижной подписью дорожек слева и пустыми ячейками там, где наград нет. Премиальный пропуск покупается за общую валюту. Кейсы выдаются наградами уровней, открываются из отдельного инвентаря и не покупаются напрямую; демонстрационное открытие стоит 200 жетонов и сопровождается многосекундной рулеткой: выигрыш не подсвечивается и не раскрывается заранее, после остановки появляется отдельная карточка награды. Общая валюта демонстрационно поступает из конвертации БОА/БУА и одобренных отзывов, не за учебные оценки. Для постоянного хранения, атомарной защиты от параллельных дублей и месячной конвертации необходимо подключение серверных API.

Староста в модели является студентом с признаком полномочий, а не отдельной ролью. В кабинете преподавателя `/teacher/students` можно рассматривать заявки на вступление в закреплённые группы, просматривать состав групп и назначать старост. Одобренный студент появляется в составе группы; назначение старосты обновляет права студенческого кабинета. Форма заявки на справку собирает тип и способ получения; комментарий необязателен. Поддерживаются статусы «Подана», «В обработке», «Готова», «Выдана», «Отклонена» и «Отменена».

В учебной части доступны отдельные экраны обработки заявлений на справки и составления недельного расписания. В демо-режиме статус заявки проходит только допустимые этапы, а расписание не позволяет пересекающиеся занятия одной группы.
