# ПТУ-Сошиал

Клиент и backend-сервис для студента, преподавателя, организатора мероприятий и учебной части. Пользовательские данные загружаются через авторизованный API и хранятся в базе данных; отключённые или отсутствующие данные показываются как пустое состояние, а не заменяются демонстрационными записями.

## Запуск

```sh
npm install
npm run dev
```

Для production-сборки выполните `npm run build`, для локального просмотра сборки — `npm run preview`. Backend находится в `../backend`, требует Java 21 и запускается из его каталога командой `./mvnw spring-boot:run`. Перед запуском настройте параметры базы данных и сервисов в окружении backend.

## Маршруты

- `/student` — кабинет студента
- `/student/profile` — профиль студента и история начислений
- `/student/awards` — общая лента наград за учёбу и активность
- `/student/leaderboard` — рейтинги по АР, БОА и БУА с фильтрами группы и курса
- `/student/people/:studentId` — публичный профиль студента, показатели и последние награды
- `/student/tasks` — список заданий и форма сдачи
- `/student/events` — мероприятия и запись
- `/student/group-confirmation` — подтверждение заявок старостой
- `/student/wallet` — баланс и история операций
- `/student/battle-pass` — ПТУ-пасс: все 50 уровней в одной горизонтальной шкале, бесплатная и премиальная дорожки, прогресс только за АР
- `/student/inventory` — инвентарь и получение серверной награды из кейса
- `/student/certificates` — заявка на справку и её статус
- `/academic-office/certificates` — обработка заявок на справки
- `/academic-office/schedule` — создание и просмотр расписания занятий по дням
- `/teacher` — кабинет преподавателя
- `/teacher/submissions` — таблица сдач студентов и проверка работ
- `/teacher/events` — создание мероприятий, запись закреплённых групп и начисление БОА/БУА после завершения
- `/organizer` — кабинет организатора мероприятий
- `/organizer/events` — управление мероприятиями и подтверждёнными участниками
- `/academic-office` — кабинет учебной части
- `/register` — заявка студента
- `/verify-email` — подтверждение электронной почты
- `/teacher/activate?token=...` — установка пароля по приглашению преподавателя

Корневой и неизвестные маршруты перенаправляются в кабинет студента. Базовый URL API задаётся переменной окружения `VITE_API_BASE_URL`; если она не задана, используется `/api`.

Светлая или тёмная тема переключается кнопкой в верхней панели и сохраняется для следующих посещений. В меню слева выбираются рабочая роль и разделы; повторного блока профиля внизу меню нет. Баланс жетонов студента отображается в верхней панели и ведёт в кошелёк.

Интерфейс использует синий акцент, светлую и тёмную темы, общие стили карточек, форм и таблиц. Макеты адаптированы для узких экранов; анимации учитывают системную настройку уменьшения движения.

Авторизация, регистрация, подтверждение почты, активация приглашений, профиль, справки, сообщество, задания и сдачи используют backend API. Для заданий и сдач сохраняются данные и содержимое файлов. Учебная часть может прикрепить к заявке на справку PDF-файл размером до 20 МБ; студент скачивает его после одобрения заявки. Ошибки backend отображаются в интерфейсе; локальное состояние не используется как имитация успешной записи.

Мероприятия, групповые регистрации, подтверждение участия, отзывы, начисления БОА/БУА, кошелёк, сезонный ПТУ-пасс, награды, кейсы и расписание работают через API с постоянным хранением. Начисления и изменения кошелька выполняются сервером. Владелец и права определяются авторизованным пользователем, а не присланным клиентом идентификатором. Студент отправляет старосте запрос на подтверждение принадлежности к своей группе; преподаватель или староста обрабатывает запрос на сервере.
